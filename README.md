# NetSimClient 
## 상태 : 진행 중(프로토 타입)

### 연관 프로젝트
+ 백앤드 서버 : [NetSim (Dedicated Server)](<https://github.com/LEEHAESUGIT/NetSim>)

# 개발환경
+ Engine : Unity 6000.3.9f1
+ IDE : Visual Studio 2022
+ Language & Runtime : C#(.NET 8.0 호환 / C# 12+)


# 소개
"NetSimClient"는 직접 구축한 C# 데디케이티드 권위형 서버(NetSim)와의 비동기 소켓 통신을 검증하고 네트워크 동기화 기법(클라이언트 예측 , 보간 등) 을 연구하기 위해 제작 중인 Unity 기반의 프로토타입 클라이언트 입니다.

상용 네트워크 엔진에 의존하지 않고, 자체 설계한 바이너리 패킷 프로토콜을 유니티 메인 스레드 및 라이프 사이클(MonoBehaviour)환경에 맞춰 완벽하게 이식 하는것을 목표로 개발하고 있습니다.
최대 8인 수용 가능한 단일 코어 서버 와 연계되어 서버자체가 호스트가 되고, 클라이언트는 게스트로 존재하게 됩니다.
## 조작
이동 : UPArrow , DownArrow , LeftArrow , RightArrow


# 핵심 아키텍처 및 구현 로직
## 서버 아키텍처의 유니티 이식
데디케이티드 서버에서 사용한 모듈식 구조를 클라이언트에서도 동일하게 적용했습니다.
다만 유니티 환경 특성을 고려하여, 각 모듈을 MonoBehaviour로 래핑하여 유니티의 라이프사이클 안에서 네트워크 데이터를 안전하게 처리할 수 있도록 설계 했습니다.

## 완전한 대칭형 바이너리 직렬화
서버와 클라이언트 간의 패킷 파편화를 막기 위해 , 고정헤더와 가변 바디로 이루어진 순수 바이트 스트림 프로토콜의 직렬화/역직렬화 로직을 서버와 절대적으로 동일하게 구성했습니다.
이를 통해 불필요한 데이터 파싱 오버헤드를 줄이고, 데이터의 정합성을 보장합니다.

```
│ │ ├──── Module/                    # 서버 아키텍처와 대칭되는 래퍼 (MonoBehaviour)
│ │ │ ├──── GameModule.cs
│ │ │ └──── NetworkModule.cs
│ │ │
│ │ └──── NetworkPackage/            # 서버(NetSim) 코어와 동일한 구조의 네트워크 레이어
│ │   ├──── AsyncTask/               # IngameSendTask 등 비동기 송수신 스레드 작업

│ │   ├──── Function/                # GamePacketProcess, PacketSender

│ │   ├──── Packet/                  # 바이너리 패킷 클래스(Move, Spawn) 및 직렬화 툴(Tool)
│ │   ├──── Router/                  # Game/System PacketRouter, Pipe 및 Handle 로직
│ │   ├──── Service/                 # GamePacketApplyService, SessionLifeCycleService

│ ├──── Scenes/                      # 테스트 환경 씬 (SampleScene)
│ └──── Material/                    # 오브젝트 시각화용 메테리얼
│
└──── README.md
```
# 요약
데디케이티드 게임 서버에서 활동하기 위해 접근할수 있는 클라이언트 프로그램. TCP/IP 통신 기반의 커스텀 바이너리 패킷 프로토콜을 사용해 접속한 다른 클라이언트와 오브젝트 포지션 등을 렌더링하고 시각화 합니다.

# 회고
서버를 만들때는 비동기 I/O처리와 메모리에 집중했다면, 클라이언트를 연동하는 과정에서는 '네트워크 스레드와 유니티 메인스레드 간의 데이터 동기화' 그리고 '바이트 스트림 프로토콜의 직렬화/ 역직렬화 로직의 대칭구조' 를 신경써서 구현했습니다.
하지만 실제 환경에서 테스트를 진행하는 과정에서 새로운 난관에 직면했습니다. 패킷의 송수신 지연과 서버의 처리시간으로 인한 미세한 타이밍 차이가 발생했고, 결과적으로 서버가 가상환경에서 계산한 가상의 룸(Room)내 객체 좌표와 클라이언트의 유니티 화면에 렌더링된 좌표 간에 불일치 현상이 발생하는것을 확인했습니다.
저는 이 문제를 해결하기 위해 두가지 개선 플랜을 수립했습니다.
1. 주기적 동기화 및 보간 : 1초단위의 포지션 체크 패킷을 도입하여, 서버의 절대 좌표 간의 오차를 계산하고 부드럽게 위치를 보정하는 로직을 기획했습니다.
2. 네트워크 틱레이트 도입 : 클라이언트와 서버 모두에 고정된 네트워크 틱레이트를 구현하여 렌더링 프레임과 독립적으로 패킷 연산 주기를 일치시켜 보간의 정확도를 극대화 하는 아이디어를 도출했습니다. 

현재 이 동기화 아이디어를 적용하기 위해, 클라이언트 아키텍처의 객체 라이프사이클 재설정 및 파이프라인 전면 수정 등 단순한 기능 추가를 넘어서 대규모 리펙토링을 진행중 입니다.
비록 아직 미완성 상태지만, 네트워크를 구현할때 생길 수 있는 오차와 오류를 직접 체감하며 해결방법을 고민하는 프로젝트가 되고 있습니다.

# 앞으로의 과제
+ 아키텍처 개선 : 현재 진행 중인 리펙토링 과정에서 OOP원칙을 바탕으로 낮은 결합도를 지향하고 있습니다. 네트워크 레이어와 인게임 로직 간의 의존성을 최대한 분리하는것이 1차 목표입니다.
+ 동기화 기능 고도화 : 단단하게 다져진 기틀 위에 보간 기능과 틱레이트 동기화 시스템을 안착시켜 시각적으로 끊김 없는 안정적인 플레이 환경을 구축할 계획입니다.
+ 다중 접속 및 세션 관리 : 현재 다중접속은 확인 되었으나, 세션 관리가 아직 미흡합니다. 다중 클라이언트 접속 시 다른 플레이어들의 접속및 종료 상태를 알리는 브로드캐스팅 패킷 처리 로직을 추가하여 세션 관리를 고도화해 나갈 예정입니다.
